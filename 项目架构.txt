# 六、整体调用关系（一句话串起来）

```
evolution_search.main
   └─ pymoo.minimize → nsganet.nsganet (NSGA-II: binary_tournament + RankAndCrowdingSurvival)
        └─ NAS._evaluate → {micro|macro}_encoding.convert → train_search.main
              ├─ micro_encoding.decode / macro_encoding.decode → 建模型
              ├─ micro_models.PyramidNetworkCIFAR / macro_models.EvoNetwork
              │     └─ micro_operations.OPS / macro_decoder.*（组装层）
              ├─ cifar10_search.CIFAR10（4万训练+1万验证）
              ├─ misc.utils（Cutout/drop_path/统计）
              └─ misc.flops_counter（算 FLOPs）→ 返回 {valid_acc, flops} → out["F"]
```

**两个搜索空间的分工**：`micro` 搜 cell 内部连接（算子+输入），用 `PyramidNetworkCIFAR` 堆叠；`macro` 搜 phase 间连接矩阵，用 `EvoNetwork`+`DenseGenomeDecoder`。两者共享同一套 NSGA-II 引擎和编码/训练框架，这也是代码结构上"engine 与 search space 解耦"的设计精髓。

如果你希望我针对某个具体函数做**逐行级**解读（例如 `calc_crowding_distance` 的数值细节，或 `ResidualPhase.build_dependency_graph` 的"修复"逻辑），告诉我即可
